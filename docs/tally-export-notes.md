# Tally XML export notes

Generated by `lib/data/tally-export.ts`. Confirmed against TallyPrime XML integration docs and published voucher import examples (ENVELOPE / HEADER / BODY, `TALLYREQUEST` Import, `TYPE` Data, `ID` Vouchers). Fields below were not verified against a live Tally company.

## Used with reasonable confidence

- Envelope: `ENVELOPE` → `HEADER` + `BODY`.
- Header: `VERSION` 1, `TALLYREQUEST` Import, `TYPE` Data, `ID` Vouchers.
- Body: `DESC/STATICVARIABLES/SVCURRENTCOMPANY`, then `DATA` with one `TALLYMESSAGE` per voucher.
- Voucher: `DATE` and `EFFECTIVEDATE` as `YYYYMMDD`, `VOUCHERTYPENAME` Receipt (money in) or Payment (money out), `NARRATION`, `PARTYLEDGERNAME` (counterparty), `REFERENCE` (seed transaction id).
- Ledger legs: `ALLLEDGERENTRIES.LIST` with `LEDGERNAME`, `ISDEEMEDPOSITIVE` Yes on the debit (amount negative), No on the credit (amount positive). Amounts are major units with two decimals.
- Cost centre: `CATEGORYALLOCATIONS.LIST` → `COSTCENTREALLOCATIONS.LIST` / `NAME` = the transaction **tag**. This is the field the demo merchant currently types by hand. The cost-centre amount matches the P&amp;L leg.

## Unsure / guessed

- Whether this merchant's Tally company name must match `SVCURRENTCOMPANY` exactly (`Al Bidda Trading W.L.L.`).
- Whether `TALLYREQUEST` should be the token `Import` or the phrase `Import Data` (both appear in published samples).
- Whether one `TALLYMESSAGE` wrapping every voucher is required instead of one message per voucher.
- `OBJVIEW="Accounting Voucher View"` on `VOUCHER`.
- Bank/gateway ledger names (`Ahli Bank`, `SkipCash`, `Shopify`, `Payment Link`, `Cash`) and P&amp;L ledger names (`Sales`, `Salaries`, or the tag for other expenses). Tally import typically requires those ledgers and cost centres to exist already.
- Cost category name `Primary Cost Category`.
- Putting the cost centre on the Sales/expense leg only, not the bank leg.
- Using Payment vouchers for refunds (direction out, type refund) rather than Credit Note.
- Excluding pending transactions (they are not in Money In / Revenue). The spec said “one voucher per transaction in the selected range”; pending rows in range are omitted.
- `GUID` / `REMOTEID` / `VOUCHERNUMBER` — omitted.
- VAT tags — omitted because this merchant is not VAT registered.
- Whether Qatar/QAR companies need extra currency tags.

Do not treat this file as a certified Tally import until it is loaded into TallyPrime.
